API 概述

功能介绍

Gridea REST API 为静态博客写作客户端提供了完整的后端接口支持，主要功能包括：

  • 文章管理：创建、发布、更新和删除文章
  • 内容验证：Markdown 内容格式和安全验证
  • 状态监控：文章发布状态和系统健康检查
  • Webhook 支持：与第三方服务的集成
  • 部署管理：多平台部署支持

认证说明

重要提示：当前 API 版本不需要认证密钥，但生产环境建议启用 API 密钥认证。

API 密钥认证（推荐）

Authorization: Bearer your-api-key

请求头认证

X-API-Key: your-api-key

基础使用方法

基础 URL

开发环境: http://localhost:4000
生产环境: https://your-domain.com

请求格式

所有 API 请求都使用 JSON 格式，请求头应包含：

Content-Type: application/json
Accept: application/json

响应格式

所有响应都是 JSON 格式，包含以下结构：

{
  "success": true,
  "data": {},
  "message": "操作成功",
  "timestamp": "2024-01-01T00:00:00Z"
}

端点文档

目录

  • GET /api/health - 健康检查
  • POST /api/v1/articles/publish - 发布文章
  • POST /api/v1/validate/markdown - 验证 Markdown
  • GET /api/v1/articles/:id/status - 获取状态
  • POST /api/v1/webhook/test - 测试 Webhook

GET/api/health

描述：检查 API 服务状态和可用性

请求参数

无

响应

字段 类型 描述
status string 服务状态：healthy, degraded, unhealthy
timestamp string 检查时间戳
version string API 版本
uptime number 服务运行时间（秒）

POST/api/v1/articles/publish

描述：发布新文章或更新现有文章

请求参数

字段 类型 必需 描述
title string 是 文章标题
content string 是 文章内容（Markdown 格式）
tags array 否 标签数组
published boolean 否 是否立即发布（默认：true）
slug string 否 URL 友好的文章标识符
meta object 否 元数据信息

响应

字段 类型 描述
id string 文章 ID
title string 文章标题
slug string URL 标识符
status string 发布状态：published, draft, failed
publishedAt string 发布时间
url string 文章 URL

POST/api/v1/validate/markdown

描述：验证 Markdown 内容的格式和安全性

请求参数

字段 类型 必需 描述
content string 是 要验证的 Markdown 内容
options object 否 验证选项

验证选项

字段 类型 默认值 描述
maxContentLength number 100000 最大内容长度
maxLineLength number 10000 最大行长度
allowedImageFormats array ['jpg', 'jpeg', 'png', 'gif', 'webp', 'svg'] 允许的图片格式
requireTitle boolean true 是否要求标题

响应

字段 类型 描述
isValid boolean 验证结果
errors array 错误信息数组
warnings array 警告信息数组
suggestions array 建议信息数组
statistics object 内容统计信息

GET/api/v1/articles/:id/status

描述：获取文章的发布状态和详细信息

路径参数

参数 类型 必需 描述
id string 是 文章 ID

响应

字段 类型 描述
id string 文章 ID
title string 文章标题
status string 状态：draft, publishing, published, failed
progress number 发布进度（0-100）
createdAt string 创建时间
updatedAt string 更新时间
publishedAt string 发布时间
deployment object 部署信息

POST/api/v1/webhook/test

描述：测试 Webhook 配置和连接

请求参数

字段 类型 必需 描述
url string 是 Webhook URL
event string 否 测试事件类型
headers object 否 自定义请求头
payload object 否 测试负载数据

响应

字段 类型 描述
success boolean Webhook 调用是否成功
statusCode number HTTP 状态码
responseTime number 响应时间（毫秒）
response object 服务器响应
error string 错误信息（如果有）

错误代码说明

HTTP 状态码

状态码 含义 说明
200 OK 请求成功
201 Created 资源创建成功
400 Bad Request 请求格式错误或参数无效
401 Unauthorized 认证失败或缺少认证信息
403 Forbidden 权限不足
404 Not Found 请求的资源不存在
422 Unprocessable Entity 数据验证失败
429 Too Many Requests 请求频率超过限制
500 Internal Server Error 服务器内部错误
503 Service Unavailable 服务暂时不可用

常见问题解决方案

1. 认证失败 (401)

症状：收到 401 Unauthorized 错误
原因：API 密钥缺失、过期或无效
解决方案：
  • 检查请求头中是否包含正确的 Authorization 头
  • 确认 API 密钥是否有效且未过期
  • 验证 API 密钥是否有足够的权限

2. 数据验证失败 (422)

症状：收到 422 Unprocessable Entity 错误
原因：请求数据格式错误或缺少必填字段
解决方案：
  • 检查 JSON 格式是否正确
  • 确认所有必填字段都已提供
  • 验证字段值是否符合预期格式
  • 查看错误详情中的具体验证失败原因

3. 请求频率限制 (429)

症状：收到 429 Too Many Requests 错误
原因：请求频率超过 API 限制
解决方案：
  • 实现请求重试机制
  • 使用指数退避算法
  • 批量处理请求以减少调用次数
  • 联系支持团队请求提高限制

4. 服务器错误 (500)

症状：收到 500 Internal Server Error 错误
原因：服务器内部处理错误
解决方案：
  • 检查请求数据是否异常
  • 稍后重试请求
  • 查看服务状态页面
  • 联系技术支持

安全说明

API 密钥管理

获取 API 密钥

  1. 登录 Gridea 管理后台
  2. 进入"设置" → "API 设置"
  3. 点击"生成新密钥"
  4. 复制并妥善保存 API 密钥

API 密钥安全最佳实践

  • 不要硬编码：避免在代码中直接写入 API 密钥
  • 使用环境变量：将 API 密钥存储在环境变量中
  • 定期轮换：定期更换 API 密钥
  • 权限最小化：只授予必要的权限
  • 监控使用情况：定期检查 API 使用日志

安全最佳实践

1. 传输安全

  • HTTPS：始终使用 HTTPS 协议进行 API 调用
  • 证书验证：验证服务器证书的有效性
  • 加密传输：敏感数据必须加密传输

2. 认证安全

  • Bearer Token：使用 Bearer Token 认证方式
  • 短期令牌：使用短期有效的访问令牌
  • 刷新令牌：实现令牌刷新机制

3. 数据安全

  • 输入验证：验证所有输入数据
  • 输出编码：对输出数据进行编码
  • SQL 注入防护：使用参数化查询
  • XSS 防护：过滤用户输入

4. 访问控制

  • IP 白名单：限制 API 访问的 IP 地址
  • 速率限制：实现 API 调用频率限制
  • 权限检查：基于角色的访问控制

5. 监控和日志

  • 访问日志：记录所有 API 访问
  • 错误日志：记录详细错误信息
  • 异常监控：监控异常访问模式
  • 安全审计：定期进行安全审计

安全示例代码

JavaScript 示例

// 安全的 API 调用示例
class GrideaAPI {
  constructor(apiKey, baseUrl = 'https://api.gridea.com') {
    this.apiKey = apiKey;
    this.baseUrl = baseUrl;
  }

  async request(endpoint, options = {}) {
    const url = `${this.baseUrl}${endpoint}`;
    const headers = {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${this.apiKey}`,
      ...options.headers
    };

    try {
      const response = await fetch(url, {
        ...options,
        headers
      });

      if (!response.ok) {
        throw new Error(`HTTP error! status: ${response.status}`);
      }

      return await response.json();
    } catch (error) {
      console.error('API request failed:', error);
      throw error;
    }
  }

  async publishArticle(articleData) {
    return this.request('/api/v1/articles/publish', {
      method: 'POST',
      body: JSON.stringify(articleData)
    });
  }
}

// 使用示例
const api = new GrideaAPI(process.env.GRIDEA_API_KEY);
api.publishArticle({
  title: '安全示例',
  content: '# 安全示例\n\n这是一个安全调用 API 的示例。'
}).then(result => {
  console.log('发布成功:', result);
}).catch(error => {
  console.error('发布失败:', error);
});

Python 示例

# 安全的 API 调用示例
import requests
import os
from typing import Dict, Any, Optional

class GrideaAPI:
    def __init__(self, api_key: str, base_url: str = 'https://api.gridea.com'):
        self.api_key = api_key
        self.base_url = base_url
        self.session = requests.Session()
        self.session.headers.update({
            'Content-Type': 'application/json',
            'Authorization': f'Bearer {self.api_key}'
        })

    def request(self, endpoint: str, method: str = 'GET',
                data: Optional[Dict[str, Any]] = None) -> Dict[str, Any]:
        url = f"{self.base_url}{endpoint}"

        try:
            response = self.session.request(
                method=method,
                url=url,
                json=data
            )
            response.raise_for_status()
            return response.json()
        except requests.exceptions.RequestException as e:
            print(f"API request failed: {e}")
            raise

    def publish_article(self, article_data: Dict[str, Any]) -> Dict[str, Any]:
        return self.request('/api/v1/articles/publish', 'POST', article_data)

# 使用示例
api = GrideaAPI(os.getenv('GRIDEA_API_KEY'))
try:
    result = api.publish_article({
        'title': '安全示例',
        'content': '# 安全示例\n\n这是一个安全调用 API 的示例。'
    })
    print('发布成功:', result)
except Exception as e:
    print('发布失败:', e)
